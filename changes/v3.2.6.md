## v3.2.6

### Fixed
- `runRegula()` no longer hangs forever when called with an empty `paths` array. With no path
  arguments the regula CLI falls back to reading stdin, and `execFile` always hands the child an
  open stdin pipe, so the WASI process blocked on read and the promise never settled (neither
  resolved nor rejected). The child's stdin is now closed explicitly, so the call returns an empty
  result set instead. Passing input paths was never affected.
- `build-wasi.sh` now stamps `version.Version` and `version.GitCommit` via ldflags, matching the
  Makefile. Previously the WASI build reported `unknown-version, build unknown-commit` while the
  native binary reported the real values.

### Changed
- `test/test-wasi.js` honours a `WASI_RUNTIME` environment variable (default `node`) instead of
  hardcoding `node`, so the parity suite can be pointed at another runtime.
